# 4.4.6 Roteiro de Testes Funcionais 
Este documento define os **casos de teste funcionais** do software do Micromouse com base nos requisitos funcionais e nas histórias de usuário (HUs) publicadas no GitHub Projects. Os testes validam as funcionalidades do sistema como o comportamento embarcado do robô (calibração, sensoriamento, locomoção e navegação), a transmissão e validação da telemetria, a visualização em tempo real, a persistência e a consulta dos resultados.

Os casos estão divididos em dois grupos:

- **CT-S:** sistema web e *backend* (recepção de telemetria, *dashboard*, banco de dados, histórico e acesso).
- **CT-SE:** sistema embarcado (firmware do ESP32).

A linha **Rastreabilidade** de cada caso traz o link da HU que o teste comprova e os critérios de aceitação cobertos. **CA1** e **CA2** são o primeiro e o segundo critério "Dado… quando… então…" da issue da HU.

### Evidências de execução

O último passo de cada caso diz qual evidência deve ser guardada para que o teste possa ser auditado. Os tipos usados são:

| Evidência | Formato | Uso |
| :--- | :--- | :--- |
| Log serial | `.txt` exportado do monitor serial | Estados internos do firmware (leituras, célula, orientação, erros) |
| Log do servidor / de eventos | `.txt` ou `.csv` | Recepção, descarte de pacotes e eventos do *backend* |
| Consulta ao banco | `.csv` com o resultado da consulta | Conferência do que foi gravado |
| Captura de tela | `.png` | Estado da interface web em um passo específico |
| Gravação de tela / vídeo | Link externo (arquivos acima de 5 MB não vão para o repositório) | Comportamento dinâmico do robô ou da interface |
| Planilha de medição | `.csv` ou `.xlsx` | Medidas manuais (régua, transferidor, cronômetro) e comparações esperado × obtido |
| Relatório de execução | `.md` | Resumo do teste: data, versão do firmware/sistema, executor, resultado (aprovado/reprovado) e links das demais evidências |

As evidências de cada execução ficam em `docs/evidencias/<código do caso>/`, com nomes no padrão `<código>_<AAAA-MM-DD>_exec<n>.<ext>` (ex.: `CT-SE03_2026-10-15_exec1.txt`). Todo caso executado gera também um relatório de execução nessa pasta.

### Telas do sistema web

Os nomes de telas, botões e campos usados nos casos CT-S seguem os protótipos de interface do Figma. Todas as telas são acessadas pelo menu lateral **Navegação**.

| Item do menu | Título da tela | Elementos usados nos testes |
| :--- | :--- | :--- |
| Dashboard | Visão Geral | Cards "Status do Robô", "Bateria", "Estado da Corrida" e "Labirinto Atual"; painel "Última Execução" com o botão "Ver detalhes"; painel "Status do Sistema" ("Conexão com o Micromouse", "Recebimento de telemetria") |
| Monitoramento | Monitoramento em Tempo Real | Cards "Conexão", "Labirinto", "Estado da Corrida" e "Tempo"; "Mapa do Labirinto"; painel "Telemetria" (Bateria, Velocidade, Posição, Status da Execução, Comunicação); "Eventos Recentes" |
| Histórico | Histórico de Corridas | Filtros "Labirinto", "Resultado", "Tentativa" e "Data da execução"; tabela "Execuções Registradas"; botões "Exportar PDF", "Exportar CSV" e "Ver detalhes" |
| Histórico → Ver detalhes | Detalhes da Corrida | Resumo (ID da corrida, Data e hora, Labirinto, Tentativa, Resultado); "Trajeto no Labirinto"; "Linha do Tempo da Execução"; botões "Exportar PDF", "Exportar CSV" e "Voltar ao histórico" |
| Logs | Logs e Eventos | Filtros "Tipo de evento", "Origem", "Data da ocorrência" e "Busca"; botões "Limpar filtros" e "Atualizar"; tabela "Registro de Eventos"; painel "Detalhes do evento" |

## Sistema Web e Backend

### CT-S01 - Recepção de telemetria do Micromouse

| Parâmetro | Detalhe |
| :--- | :--- |
| **Código do caso de teste** | CT-S01 |
| **Nome do caso de teste** | Recepção de telemetria |
| **Rastreabilidade: Link do(a) RF/HU associado(a)** | [RF05-S / HU #88 - Transmissão de Telemetria][hu88] (CA1, CA2) |
| **Objetivo do caso de teste** | Verificar se o sistema recebe continuamente os pacotes de telemetria do Micromouse com todos os campos e na frequência definida. |
| **Pré-condições do sistema para o teste ser realizado, quando se aplicar** | Micromouse ligado e conectado à mesma rede Wi-Fi do servidor; *backend* em execução com o log de recepção habilitado. |
| **Descrição dos procedimentos a serem executados para o teste** | 1. Iniciar uma corrida no labirinto 4 x 4 de testes<br>2. Registrar no servidor os pacotes recebidos durante 30 s<br>3. Conferir os campos de cada pacote e contar os pacotes por segundo<br>4. Salvar como evidência o log de recepção do *backend* (`.txt`) e o CSV com os pacotes recebidos e a contagem por segundo |
| **Resultado esperado para o teste ser aprovado (pós-condição após realizado o teste)** | Cada pacote traz identificador da corrida, número de sequência, *timestamp*, célula, orientação, velocidade, tensão da bateria e status; o servidor reconhece e processa todos; a taxa de recepção é de pelo menos 5 pacotes/s e a numeração é contínua, sem perdas. |
