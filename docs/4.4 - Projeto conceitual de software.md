## 3. Arquitetura da Solução de Software (Visões 4+1)
O software foi modelado no padrão Cliente-Servidor Distribuído, utilizando **C++ (PlatformIO)** para a lógica de navegação autônoma embarcada no ESP32, **Python (FastAPI)** para o back-end da telemetria e **React** para a interface do dashboard. O sistema operacional FreeRTOS gerencia as prioridades de hardware para garantir a latência máxima de 50ms.
- **Arquivo de Saída:** 🔗 [Acessar Detalhamento da Arquitetura 4+1](./4.4.3%20-%20Arquitetura%20da%20Solucao.md)

---

## 4. Persistência de Dados (MER/DER)
Foi adotado um banco de dados relacional **PostgreSQL**, estruturado em tabelas ligadas por chaves estrangeiras. Este formato assegura o cumprimento do modelo ACID, garantindo a integridade dos pacotes de telemetria armazenados localmente e na nuvem.

- **Arquivo de Saída:** 🔗 [Acessar Dicionário de Dados e Restrições de Integridade](./4.4.4%20-%20Persistencia%20de%20Dados.md)
